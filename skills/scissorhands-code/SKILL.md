# 代码减法

只删没人用的东西。判定靠证据，不靠直觉。

## 三问

现在有人用它吗。删了谁会挂。加回来要多久。任一条答不上来就别删。

## 候选

只有一个实现的接口与工厂、未使用的参数与配置开关、复述式注释、被注释掉的旧代码、为将来预留的钩子与占位、无谓防御（内部调用的重复校验、不可能为 None 的判空）、一次转手的中间变量、日志噪音、多余依赖、文档里的自夸。

## 不删

错误处理与边界校验（IO、网络、权限、金额、并发）、安全相关（鉴权、转义、限流、脱敏）、可观测性埋点、公开契约（API、schema、CLI、文件格式，要改属破坏性变更，单独提交写迁移）、许可证头、兼容层、测试。

## 证据

"看起来没人用"不是证据。给出命令与输出：

```
git grep -n "符号名" -- ':!docs'
```

零命中才算没人用。只在定义处出现一次的是私有实现，可直接删。被配置或反射调用的不算零命中。

## 门禁

```
python tools/scissors.py code --repo . --test-cmd "你的测试命令"
```

只有删除行且测试通过才算减法。出现新增行说明混了别的东西：承认它是普通改动，或拆成两次提交。

## 台账

工程型交付给台账，一行一条：删了什么、凭什么、证据。不写"顺手优化""更清晰"。

## 常见失败

- 删抽象层的同时改了调用点。这是重构，走正常评审。
- 为了让测试通过去改断言。测试是证据，不是障碍。
- 删掉 `if not path.exists()`，因为"上游检查过"。拿不出来源就是删错。
- 删完留下空文件或空目录。空壳也是新增。
