# 汇报文档瘦身

唯一的判断标准：上级看完，能不能在五分钟内做出批准或不批准的决定。能，合格。不能，说明还太长。

## 动刀顺序

1. 先写清楚要上级定什么，一句话，放第一段。不是背景，不是目的，是要批的那件事。
2. 只留决策需要的信息：有哪几个选项、各自代价、风险、影响面、要多少钱多少人多久。
3. 论证、推导、实施步骤、历史沿革、资料摘录移出正文。确实需要复核的进附件，不需要的直接删。
4. 每段过一遍：删掉这段，上级的批准决定会变吗？不变就删。
5. 数一遍字数。正文 1000 至 1800 字，约 2 至 3 页。超了就继续删，不是压缩字号。

## 删

- 背景铺陈：行业趋势、公司战略、上级已经知道的事。
- 方法论介绍：用了什么框架、参考了哪些案例、团队怎么想的。
- 自我论证：为什么这个方案好。超过三句就是辩护，不是汇报。
- 数据来源的完整说明。留一句口径，其余进附件。
- 实施步骤与排期细节。批准之后才需要，放在附件。
- 感谢、展望、会后附言、"下一步我们将"。
- 重复总结：开头说过的结论，结尾再说一遍。

## 保

- 数字与口径。口径要短但要在，一句话说清分母和统计区间。
- 代价、工期、人力占用。上级批的就是这些。
- 风险与不可逆项。删风险是最严重的过度删除。
- 选项对比。只有一个选项就不叫决策，要说明为什么没有别的。
- 待决事项：请谁在什么时间前批什么。

## 结尾

只留一句：请 X 在 Y 之前批准 Z。不写"以上供参考"，不写"欢迎指正"。

## 常见失败

- 字数压到 1800，但结论仍在第四段。失败，还是没解决上级的问题。
- 把论证搬进附录，正文仍写"详见附录"。正文要能独立成立。
- 删掉了风险段落，因为"看起来影响批准"。这是最坏的一种删。
- 段落变短了，但每段都在铺垫，只是铺垫得更简洁。

改完后跑 `python tools/scissors.py scan --file 正文.md` 看套话候选；再跑 verify 确认正文是从原稿删出来的，没有顺手改写。工具用法见 scissorhands-gate。
