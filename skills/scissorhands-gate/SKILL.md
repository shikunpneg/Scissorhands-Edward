# 交付门禁

目的是用机械检查证明"没有新增文字"，而不是靠读一遍觉得像。

## 工具位置

按顺序取第一个存在的：

1. `./tools/scissors.py`（在剪刀手仓库内工作时）
2. `~/.dsh/scissorhands/tools/scissors.py`（跑过 install.ps1 之后）
3. 都没有：改用下面的五项人工自检

只依赖 Python 3 标准库和 git，不需要安装依赖。

## 三条命令

```
python tools/scissors.py verify --original 原文.md --edited 现文.md
python tools/scissors.py scan --file 文档.md
python tools/scissors.py code --repo . --test-cmd "pytest -q"
```

`verify` 判的是子序列：现文的每一个字符都能在原文中按顺序找到，则通过。通过不代表删得对，只代表没有新增。删得对不对，回到 scissorhands 的判据。

`scan` 只给候选，不改写。输出的每条候选带行号、类别、单元边界建议动作。含数据的句子会被标成"整句保留"，因为按单元完整性不允许只删前缀。

`code` 判的是这次改动是否只有删除行。有新增行即视为改动而非减法，需要拆开提交。

常用参数：

- `--keep "术语A,术语B"`：本轮用户点名保留的词，出现在删除片段里即阻断。
- `--allow-partial-unit`：放行非完整单元删除。只在确认被删片段是合法子句时使用，默认不放行。
- `--json`：机器可读，配合 `--out report.json` 导出全量。
- `--report-limit N`：控制屏幕输出条数，默认 12 条，避免刷屏。

## 退出码

| 码 | 含义 | 处理 |
| --- | --- | --- |
| 0 | 通过 | 可以交付 |
| 1 | 有新增文字，或代码有新增行 | 撤回，只保留删除动作 |
| 2 | 删到了保护内容，或删除不在完整单元边界 | 补回原样，或缩小到完整单元 |
| 3 | scan 找到可删候选（仅 scan） | 按候选清单决定删不删 |
| 5 | 环境或用法错误 | 修命令，不要当成通过 |

交付前必须看到 0。看到 1 或 2 不许交付，也不许"解释一下为什么这样删"。

## 五项人工自检

工具跑不了时，逐项过：

1. 逐字对齐：拿现文第一个字符去原文里找，找到后从该位置继续找下一个，直到现文用完。全部能找到是按序的。剩下没用到的原文片段就是删除内容。
2. 有没有一个字是写出来的：删除过程中是否动过标点、空格、编号、换行、缩进。动过即新增。
3. 删除边界：每处删除的起点和终点是否落在句末标点、行首、行尾或段落边界。
4. 保护清单：数字、单位、链接、代码、引用、警告、用户点名项，逐项点名核对，不靠印象。
5. 删除比例：超过三成就要复核。比例本身不是错误，但超三成时误删概率显著上升。

## 改法优先级

删得不够，比删错了好。删得不够只是文档长了一点；删错了是丢信息，而且很难被发现自己丢了什么。两者之间没有权衡空间。

看到"这一段其实也可以再精简"时，先交付，不要顺手再删一刀。多删的那一刀是本次交付里唯一不可逆的动作。
