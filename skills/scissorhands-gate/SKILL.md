# 交付门禁

用机械检查证明没有新增文字，而不是读一遍觉得像。

## 工具位置

按顺序取第一个存在的：`./tools/scissors.py`（在仓库内）、`~/.dsh/scissorhands/tools/scissors.py`（装过之后）、都没有则用下面的五项人工自检。只依赖 Python 3 与 git。

## 三条命令

```
python tools/scissors.py verify --original 原文.md --edited 现文.md
python tools/scissors.py scan --file 文档.md
python tools/scissors.py code --repo . --test-cmd "pytest -q"
```

`verify` 判子序列：现文每个字符都能在原文中按序找到。通过只代表没有新增，不代表删得对。
`scan` 只给候选与单元边界，不改写。含数据的句子标成"整句保留"。
`code` 判这次改动是否只有删除行。

参数：`--keep "术语"` 指定必留词；`--allow-partial-unit` 放行非完整单元删除（默认不放行）；`--json --out` 导出全量；`--report-limit` 控制屏显条数。

## 退出码

| 码 | 含义 | 处理 |
| --- | --- | --- |
| 0 | 通过 | 交付 |
| 1 | 有新增文字，或代码有新增行 | 撤回，只保留删除 |
| 2 | 删到保护内容，或删除不在单元边界 | 补回原样，或缩到完整单元 |
| 3 | scan 找到可删候选 | 自行判断删不删 |
| 5 | 环境或用法错误 | 修命令，别当通过 |

交付前必须看到 0。看到 1 或 2 不交付，也不解释"为什么这样删"。

## 五项人工自检

1. 逐字对齐：拿现文首字符去原文找，找到后从该位置继续找下一个。全部找到即按序。
2. 有没有一个字是写出来的：标点、空格、缩进、编号、换行是否被动过。
3. 删除边界：起点终点是否落在句末标点、行首、行尾。
4. 保护清单：数字、链接、代码、引用、警告、点名项，逐项点名核对。
5. 删除比例：超过三成要复核。比例本身不是错误，但超三成时误删概率显著上升。

## 改法优先级

删得不够，比删错了好。前者只是长了一点，后者是不可逆的信息丢失，而且丢在哪往往发现不了。
