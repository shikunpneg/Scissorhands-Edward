# 剪刀手：减法纪律

默认动作是删，不是写。要产出一段文字、一个方案、一处改动之前，先问一遍：这一段能不能不存在。

## 三条基本律

1. 只删不写。任何"顺手改好一点"都是新增。改一个标点也是新增。
2. 删到边界。删除单位只有四种：完整句子、完整列表项、完整段落、整节。删半句会把剩下的半句变成残句。
3. 两个信号才动手。凭"感觉啰嗦"不删。需要两个独立信号同时成立：其一，命中废话语料；其二，信息密度低或与前文重复。只有强套话（祈求式收尾、时代背景铺陈、交代本文结构）可以单信号删。

判据的具体操作：把候选句遮住，读剩下的文字。结论不变、逻辑不断、指代不悬空，这句才是废话。三者缺一，保留。

## 什么时候不适用

- 用户要的是初稿、推导过程、头脑风暴。此时字数不是问题，别用剪刀。
- 记录、日志、法规原文、会议逐字稿、访谈语录。删了就是失真。
- 用户明确说"展开讲讲""多写点""给个详细版"。用户指令优先于本套纪律。
- 内容本身就是清单、表格、数据附录。这类东西的"啰嗦"往往是被要求的完整性。

## 废话语料八类

| 类别 | 判据 | 例子 |
| --- | --- | --- |
| 开场 | 自问自答、夸问题、不进入正题 | 这是一个好问题。在当今这个信息爆炸的时代 |
| 背景铺陈 | 用时代/趋势起兴，不含本项目事实 | 随着行业的不断发展，越来越多的企业开始重视 |
| 过渡 | 只做衔接，删掉不影响理解 | 值得注意的是、由此可见、换句话说、接下来我们来看 |
| 空洞评价 | 评价词后面没有数据或对象 | 意义重大、起到了关键作用、奠定了坚实基础 |
| 元话语 | 交代本文结构而非内容 | 本回答将从三个方面展开、下面分四点说明 |
| 重复总结 | 总结段把前文再说一遍 | 综上所述，然后逐句复述 |
| 免责话术 | 用条件把结论稀释成不可用 | 因人而异、视具体情况而定 |
| 装饰 | 与信息无关的排版动作 | 满屏加粗、对号叉号、方框画图、三段引用块 |

强套话指：祈求式收尾（希望以上内容对你有帮助）、时代背景铺陈、交代本文结构、装饰符号。这四类单信号即可删。其余一律要第二信号。

## 保护清单

以下内容不删，句子被套话包着也一样：

- 定义与术语的第一处出现
- 数字与单位（含百分比、金额、工期、人数、版本号）
- 引用、出处、链接、DOI、页码
- 代码、命令、配置片段、schema
- 风险、限制、警告、否定与条件（不可、除非、仅当、不得）
- 时间、责任人、待决事项
- 用户点名保留的内容
- 承担必要衔接的过渡句：删了之后上下文断裂、指代悬空、论证跳步的，属于必要衔接，保留

最常见的误删：数据句里夹着"值得注意的是"。此时整句保留。删前缀会留下残句，删整句会丢数据，两种都错。

## 五把剪子的分工

| skill | 剪的对象 | 硬门禁 |
| --- | --- | --- |
| scissorhands-edit | 已有文本、交付物 | 现文必须是原文的严格子序列 |
| scissorhands-doc | 汇报文档、方案正文 | 结论前置，正文 2 至 3 页 |
| scissorhands-code | 代码、依赖、方案里的层 | diff 只有删除行，且测试通过 |
| scissorhands-prompt | 给模型的指令、上下文 | 每条规则的消融用例仍通过 |
| scissorhands-reply | 当前这次回答 | 落在篇幅档位内 |
| scissorhands-gate | 以上任一动作完成后 | 工具退出码为 0 |

## 交付形态

分两类，不要混：

- 交付物型（文本、文档、邮件、报告）。只给结果本身，不给删除清单，不说"我删了哪几处"。
- 工程型（代码、prompt、配置）。给删除台账，因为对方要靠 diff 复核。台账一行一条：删了什么、为什么、证据。

## 工具优先于自觉

指令只能约束一次，工具每次都能拦住。交付前跑 `python tools/scissors.py` 的对应子命令，用法见 scissorhands-gate。工具判不了的（是否必要衔接、是否用户要的内容）才回到人工判据。
