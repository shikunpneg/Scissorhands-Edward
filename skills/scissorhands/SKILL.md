# 剪刀手

默认动作是删。写之前先问：这段能不能不存在。

## 三条基本律

1. 只删不写。改一个标点也算新增。
2. 删到边界：整句、整条、整段、整节。删半句会留残句。
3. 两个信号才动手：命中废话语料，且信息密度低或与前文重复。

## 判据

遮住候选句，读剩下的文字。结论不变、逻辑不断、指代不悬空，才是废话。三者缺一，保留。

## 八类废话语料

| 类别 | 长什么样 |
| --- | --- |
| 开场 | 这是好问题；在当今…时代；随着…的发展 |
| 过渡 | 值得注意的是；由此可见；换句话说；接下来看 |
| 空洞评价 | 意义重大；起到了关键作用；奠定坚实基础（后面没有数据） |
| 元话语 | 本回答将从三方面展开；下面分四点说明 |
| 重复总结 | 综上所述，然后把前文再说一遍 |
| 免责 | 因人而异；视具体情况而定 |
| 英文套话 | it's worth noting；hope this helps |
| 装饰 | 满屏加粗；对号叉号；方框画图；三行引用块 |

四类可单信号删：祈求式收尾、时代背景铺陈、交代本文结构、装饰符号。其余要第二信号。

## 保护清单

定义与术语首现、数字与单位、引用与出处、代码与命令、链接、风险与警告、否定与条件（不可、除非、仅当）、时间与责任人、用户点名保留项、必要衔接。

数据句里夹着"值得注意的是"时整句保留：删前缀留残句，删整句丢数据。

## 什么时候别用

初稿、头脑风暴、推导过程、逐字稿、法规原文、用户明确要详细版。

## 挑一把剪子

| 场景 | skill |
| --- | --- |
| 已有文本，只删不改 | scissorhands-edit |
| 汇报文档太长 | scissorhands-doc |
| 代码或方案里的层太多 | scissorhands-code |
| 指令、prompt、上下文膨胀 | scissorhands-prompt |
| 这次回答太啰嗦 | scissorhands-reply |
| 交付前证明没加东西 | scissorhands-gate |

## 交付形态

交付物型（文本、文档）只给结果，不给删除清单。工程型（代码、prompt）给台账：删了什么、为什么、证据。

## 别靠自觉

```
python tools/scissors.py verify --original A --edited B    # 退出码 0 才算过
python tools/scissors.py scan --file 文档.md               # 只给候选，不改写
```

工具的判据是严格子序列：现文每个字符都要在原文里按序找到。用法见 scissorhands-gate。
